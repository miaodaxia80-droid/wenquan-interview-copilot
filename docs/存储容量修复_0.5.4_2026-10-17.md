# 手机访谈存储容量修复 · 0.5.4

## 问题与原因

用户手机截图显示 42 段转写，同时提示 `storage item exceeds 64 KB`。这是手机宿主拒绝单项过大的写入。旧版 `web/app.js` 把整个应用状态（所有主题、历次访谈、转写、问题、模型归纳与引用）写入同一个 `wenquan.interviews.v1` 项，历史累积也会占用这项容量，不能把 42 段理解为固定阈值。

截图不能证明最新内容已落盘，页面显示的转写可能只在内存中。旧提示“请保持问全在前台后重试”也无法解决容量超限。

本地 SDK 的 Studio 存储实现没有执行单项 64 KB 检查，之前的模拟器验证未覆盖此限制。本轮在应用回归测试中加入强制 64 KiB 限制，并先证明旧版整项写入会失败，再验证修复。

## 保存与恢复方式

- 新增应用内 `web/interview-storage.js`。保留原插件 ID、存储权限、业务数据结构、完整原话和历史记录。
- JSON 文本按最多 8000 个 UTF-16 单元分块；每块作为 JSON 字符串保存，最坏转义与 UTF-8 编码也低于 48 KB，为 64 KB 的单项限制预留空间。中文、emoji 和分块边界代理项可无损拼接。
- 使用两组快照轮换。先写非活动组的所有分块，最后更新一个小索引。分块或索引写入失败时，上一份已提交快照仍可恢复。
- 索引响应丢失时，不假定提交未发生；下次保存前重读实际索引，避免覆盖已生效的数据组。
- 索引含块数、长度和内容校验；缺块、损坏或不兼容格式明确拒绝恢复，不用空记录覆盖。旧版整项记录在首次成功保存时迁移。
- 保存串行执行，每次保存先固定快照。成功后只清理该分组不再使用的尾块，不清空插件存储，也不触碰其他设置。
- 存储失败持续显示警告，提供“重试保存”和“导出当前访谈”；成功后移除警告。不会再把所有失败都提示为前台问题。

这是单项限制修复，不是无限存储。宿主总容量、WebView 本地存储额度、设备剩余空间和权限仍可能导致写入失败。两组快照也需要额外空间；总容量不足时请先导出备份。旧版程序不能读取新分块格式，不建议升级后回退旧版。

## 用户当前记录的保护

如果旧版仍打开报错访谈：

1. 不点击宿主顶部的 ×，不刷新、强退或直接扫码覆盖当前页面。
2. 点页面内“← 返回访谈”，再点底部“记录”，使用“导出 Markdown”。这条路径可读取当前内存中的记录，不要求先保存成功。
3. 确认导出文件实际包含刚才的完整原话，再更新 0.5.4。

新版只保证兼容读取已经存下来的旧记录。不能保证恢复从未落盘、且旧页面已经关闭的内容。本轮没有操作用户的实体手机，也未确认其真实访谈已导出或恢复。

## 验证结果

- `npm run check`、`npm test`、`npm run build`、`git diff --check` 全部通过，117/117 项测试通过。
- 新增回归覆盖：单项 64 KiB 限制下保存与恢复超过 1 MiB 的 1500 段、多主题、摘要与待处理转写；特殊字符跨块；旧数据迁移；首块、中间块、末块与索引失败；提交响应丢失后重试；并发保存顺序；旧尾块回收；缺块、校验与格式损坏。应用实际 `save` 入口也使用限额存储模拟验证。
- 浏览器创建独立标注的虚构长访谈，保留已有记录。完整状态 UTF-8 为 1,443,977 字节，分为 95 块；刷新后显示 1500 段。经页面“保存修改”编辑摘要，再模拟存储空间不足，确认持续警告及两个操作入口。恢复存储并点击“重试保存”，刷新后仍有全部 1500 段和最后修改的摘要。未调用麦克风或模型。截图保存在本地 `evidence/storage-error-retry-0.5.4.png`。
- 原生 Studio 加载 0.5.4，沿用 GM Web Bridge v2，显示协议完全匹配。已有 0.5.3 测试记录恢复成功；点击文本演练后实际 Bridge 写入 8 个分块，最后提交 `format=wenquan.chunked.v1` 的索引。停用再启用插件后，从分块恢复主题、原有 1 段虚构对话及问题记录，记录页与导出入口正常。截图：`evidence/storage-studio-recovered-0.5.4.png`。Studio 的这一步证明实际 Bridge 调用与重启恢复，64 KiB 强制限制由上述测试和浏览器适配器单独覆盖。
