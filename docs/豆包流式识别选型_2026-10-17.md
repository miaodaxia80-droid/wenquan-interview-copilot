## 选择

问全现场访谈主路径使用豆包流式语音识别模型 2.0 的双向流式优化版：

- WebSocket：`wss://openspeech.bytedance.com/api/v3/plan/sauc/bigmodel_async`
- `X-Api-Resource-Id`：`volc.seedasr.sauc.duration`
- `X-Api-Key`：Agent Plan 专属 API Key，仅在后端读取。
- 一句话/准确率优先的备选：`wss://openspeech.bytedance.com/api/v3/plan/sauc/bigmodel_nostream`。

专用文档说明：双流边发送音频边返回结果，适合低延迟转写；单流在全部音频发送完成或超过 15 秒后返回高精度结果。通用 API 文档进一步说明 async 只在结果变化时回包，推荐优于旧的逐包回应双向版本。问全以现场及时发现信息缺口为目标，因此主路径选择 async。

Agent Plan 应采用上述 `/plan/` 地址与专属 Key；不把通用 `/api/v3/sauc/` 或方舟文本推理 Base URL 填成套餐 ASR 地址。页面“开启超额后付费”按钮未操作。官方说明未开启时从套餐 AFP 抵扣；开启后、套餐额度用尽将进入后付费。购买完成不等于 ASR 鉴权和额度实测成功。

## 接入行为建议，尚未实现

1. 手机端滚动显示中间识别文字，允许后续包修订，不追加重复段落。
2. 优先验证 `enable_nonstream: true` 的双向流式加二遍识别组合：先实时出字，分句后重新识别以提高准确性。通用 API 支持该参数，Agent Plan 专用端点的真实兼容性仍需首测。
3. 开启 `show_utterances`，仅将服务确认的稳定分句（如 `definite: true`）提交为待核对原话；按会话与时间段去重，处理中间修订和停止时最终包。稳定分句并不代表识别无误或内容属实。
4. 每个稳定片段合并/节流后才请求追问分析，避免每个字都触发模型、改变眼镜提示；结束、取消、后台均关闭识别连接并拒绝旧会话结果。
5. 初始关闭 `enable_ddc` 语义顺滑，避免主动删除语气、停顿和重复表述；可先关闭 `enable_itn` 规范化，尽量保留口语文本供引文核对。标点可开启。实际识别仍可能与说话原文不一致，保留人工更正流程。
6. 分包以 200 ms 为初始值，按官方建议验证延迟与稳定性；不预设端到端固定延迟。
7. MemoMind 原生流为 16 kHz 单声道 Opus，服务文档支持 Ogg/Opus。需要做合法的流式 Ogg 封装，不能把裸 Opus 字节直接标为 Ogg。SDK 当前短录音 Ogg 帮助方法不等于已实现持续流式封装；PCM 16 kHz 是可验证的备选，但需要解码能力。

已有问全的 `/api/transcribe` 是 OpenAI 兼容的 multipart HTTP 适配，不能只改一个 URL 直接调用上述 WebSocket 二进制协议；录音按钮目前先完成短片段再上传，也还不是持续流式识别。后续需补后端 WebSocket 协议适配、插件到后端的音频流传输、结果修订和最终分句处理。文本模型仍复用当前已验证的 JoyMaas 路由。

## 首轮验收

先用已有合成语音验证专属 Key、资源 ID、套餐地址和最终转写，再用按实时节奏发送的音频确认中间结果、修订、稳定分句及取消。文件回放测试通过仍不能代替眼镜麦克风实测。最后在 Studio 核对实时文字到真实追问显示；Android/眼镜录音另作真机验收。
