# 问全演示访谈：第一个陌生用户之后

用途：用一场 6～8 分钟的两人访谈，展示问全如何帮助主持人听住细节、接住追问，并在结束后整理出有原话依据的内容。以下人物、项目、数字均为虚构，不是项目真实用户案例。

## 会前设置

- 主题：第一个陌生用户之后：一个校园工具为什么差点做不下去
- 目标：聊清楚小周做校园报名工具的起因、一次具体挫折、取舍依据和当前状态，留下可以继续写成访谈文章的材料。
- 嘉宾背景：学生开发者小周，课余维护校园报名工具。仅作为背景，不当作已经核实的事实。
- 四条主线：起点（为什么开始）、转折（哪个具体事件改变了判断）、选择（因此做了什么取舍）、后续（当前状态与下一步）。
- 边界：不讨论学校、社团及真实用户身份；不将计划说成已上线。
- 人物：小林＝主持人；小周＝嘉宾。只需两个人，自然对话即可。

在手机“访谈主题”页点击顶部“打开剧本演示预设”，主题、目标和上述四条主线会自动填好；确认后开始访谈。获得对方同意后开始录音，双方在开场自然说明角色。声音编号只区分本次采集中的声音；系统结合开场和问答判断主持人/嘉宾。不确定时会保留待识别，可人工更正。

## 两人台词稿

**小林：** 我是今天的主持人小林。谢谢你同意记录这次访谈。我们今天想聊一聊，你那个校园报名工具是怎么做起来的，尤其是你差点放弃的那一次。先从起点说吧，你为什么会做这个东西？

**小周：** 我是今天的嘉宾小周，现在还在读书。最初真没想做产品，只是社团每次活动都把报名信息散在几个群里，最后还要手工汇总。我就用周末做了个很简单的页面，能填表、导出名单，就这些。

**小林：** 那时候，你觉得做到什么程度就够了？

**小周：** 能让我们社团少整理两次表格就够了。但后来有三个我不认识的人主动来用，我突然觉得，也许可以认真做下去。

**小林：** 你刚才说“三个不认识的人”，我想先停在这个地方。有没有一件事让你觉得，他们是真的需要它？

**小周：** 有一个人在活动报名截止前给我打电话，说他的表单明明填了，但打开之后什么也没有。我当时先以为是他操作错了。后来查了一下，是我自己没有处理好保存失败的情况。

**小林：** 当时你具体怎么处理的？

**小周：** 我花了两个小时，跟他一起把报名信息补回来。那天原本想上线一个新的统计图表，最后没做。我发现他根本不关心图表好不好看，他只想确定自己填的东西还在。

**小林：** 所以这件事之后，你做了哪些调整？

**小周：** 我把统计图表停了，先加保存状态提示和失败重试。还有一件事，用户中途问我能不能批量导入名单，我也没马上答应。以前我觉得加一个功能就更有用，现在会先问，这是不是当前最影响他完成报名的事情。

**小林：** 如果当时有人给你一百万，你是不是就会休学全职做？这只是我的假设，不是说你真的拿到了钱。

**小周：** 我没有拿到融资，也没有休学。我现在还没有稳定收入，不会因为一个假设就决定全职。说实话，我还不清楚有多少人愿意持续使用，更别说付费。

**小林：** 你会不会觉得，功能少了，就很难让人愿意付费？

**小周：** 你说的“少”，是功能数量少，还是能解决的问题少？如果只用一次，我也不会付费。所以我想先找出，哪些社团每周都要整理报名，而不是每个人都加一个功能。

**小林：** 我指的是功能数量。你这个反问提醒我，得先明确真正要解决的问题。那现在维护这个工具，实际投入是多少？

**小周：** 现在只有我一个人维护，每周大概六小时，考试周会更少。固定在周三晚上处理反馈，比较紧急的保存失败会提前处理。每个月服务器费用大约六十元，还没有开始收费。

**小林：** 接下来一个月，你最想确认什么？

**小周：** 我想约五个经常组织活动的同学，看看他们下一次真实报名是怎么做的。自动提醒是我想做的功能，但目前还没做，要等看完他们的流程再决定。至于能不能减少整理时间，我现在没有数据，不能说已经提高了效率。

**小林：** 最后，如果回到刚开始的那个周末，你会提醒自己什么？

**小周：** 别急着证明自己能做很多功能，先保证别人交给你的东西不会丢。还有，别把朋友说“不错”当作真的有人会用，去看一个陌生人愿不愿意第二次打开。

**小林：** 好，今天我们就先到这里。我会把整理后的内容发给你核对数字和表述，谢谢你。

## 主持人操作与展示节奏

| 时点 | 动作 | 希望展示的作用 |
| --- | --- | --- |
| 双方开场后 | 观察转写角色；有误则在完整转写中纠正 | 自动区分主持人和嘉宾，允许人工校正 |
| 嘉宾提到“三个陌生人”后 | 留出约 2～4 秒，查看追问候选；选合适的一条再说 | 主持人不用边听边搜索下一问 |
| 嘉宾说保存失败后 | 可直接使用候选，也可按台词主动问“具体怎么处理” | 自发提问也能记录；提问不被当作嘉宾事实 |
| 谈取舍和后续投入时 | 切换主线，观察已有内容与待补问 | 不必机械从第一章问到最后一章，提前聊到的内容仍能归档 |
| “一百万”假设与嘉宾反问后 | 查看角色和原话 | 主持人假设不能变成嘉宾融资事实；嘉宾反问不应被当作换了主持人 |
| 结束时 | 点击结束访谈，等自动归纳完成；查看原话，再导出 | 得到核心内容、章节要点、待补问和完整记录 |

**现场问题由模型动态生成，具体措辞和顺序不保证与本稿相同。** 如果系统建议的问题比台词更贴切，主持人可采用建议，嘉宾按虚构设定自然回答。台词里的追问不代表系统已经生成了这些问题。网络或识别延迟时继续自然对话，不必等每句话分析完。

## 会后检查标准

归纳应保留：保存失败事件及两个小时补救、先可靠性再图表的取舍、单人每周约六小时维护、未收费、计划观察五位组织者。归纳不能写成：已经融资一百万、已经休学全职、已经上线自动提醒、已经证明提高效率。费用、投入和经历只能表述为“嘉宾表示”，仍需核对。

可以继续补问：保存失败是否再次发生、如何确定修复有效、观察五位组织者的具体招募方式。不要在嘉宾已经回答后，重复追问“是否休学”“是否融资”。

演示者可只演前半段约 3 分钟；这时没有聊到的章节应保持未展开，不能为了看起来完整而补造内容。
