## 账户与真实请求

在用户已登录 Edge 的模型详情页，使用已启用密钥的“复制 API-Key”按钮，直接写入被 Git 忽略的本机 `.env`，文件权限 `0600`。没有创建新密钥、扩大权限、充值或购买服务，没有输出完整密钥。账户 API-Key 管理页曾显示 0 条，但模型详情页随后显示可复制的已启用密钥；本次以后者及真实调用结果为准，不从空列表推断账号没有密钥。

详情页前端确认 OpenAI 兼容入口为 `https://modelservice.jdcloud.com/v1`。

| 请求 | HTTP | 实际结果 |
| --- | --- | --- |
| GET `/v1/models` | 404 | 此入口不支持该标准列表路径；不把它视为所有推理服务不可用 |
| Qwen3.5-122B-A10B Chat Completions | 400 | “该key不允许访问该模型” |
| JoyAI-VL-Interaction Chat Completions | 400 | “模型服务调用失败”；简化到最小文本请求后仍失败 |
| DeepSeek-V3.2 Chat Completions | 200 | 返回真实中文追问，报告 usage 为 40 tokens |
| DeepSeek-V4-Flash Chat Completions | 200 | 返回真实中文追问，报告 usage 为 45 tokens |

最终配置 `MODEL_BASE_URL=https://modelservice.jdcloud.com/v1`、`MODEL_NAME=DeepSeek-V4-Flash`；使用现有密钥。ASR 没有可用配置，仍明确报告未配置。

小请求记录保存在 `evidence/joymaas-live-probe.json`。`npm run probe:joymaas -- <模型名>` 可重新测试，会发生真实服务调用；默认输出脱敏结果并覆盖该探测报告。

## 完整分析链路与观察到的问题

用真实本机 HTTP 服务调用 `/api/analyze`，再经 JoyMaas 调用 DeepSeek-V4-Flash，最后用前端相同 `applyAnalysis` 进行二次校验和状态写入。三段输入均为新写的虚构材料，没有使用固定演示输出：

1. FDE：普通咨询和值班客服、投诉主管不回复且没有统一办法。
2. 用户研究：上周报名停在手机验证页，三次没有收到验证码。
3. 否定与未来期望：当前不允许 AI 修改工单，未来希望简单咨询自动关闭但尚未批准。

第一轮三段均返回 200，通过结构与逐字引文校验；但发现模型把“没有统一办法”和“想报名”判得过于完整，并把未来愿望归入假设。保留原始报告 `evidence/joymaas-live-analysis-before-prompt.json`。

收紧了通用提示词：围绕清单问题的实际要求判断完整性；不知道怎么处理不算处理规则已明确；区分当前限制、未来愿望和假设。第二轮三段也均返回 200，通过程序校验，总响应分别为 2697、3798、2486 ms。报告为 `evidence/joymaas-live-analysis.json`。

第二轮 FDE 正确保留“主管不回复”规则为含糊，未来愿望按 future 保留；同时仍观察到语义偏差：用户研究的“未尝试其他办法”没有直接原话支持，当前否定的类型仍被归为 current。**因此这里只能报告链路、引用和结构通过，不能宣称模型语义已全部正确。** 清单状态和模型陈述仍需人工核对。这三条属于调试材料，不是独立评估集，也没有准确率结论。

这六次完整分析与上述小请求的实际账单未读取；只保留服务返回的 token 信息，不宣称免费或给出未经核实的费用。

## 问全 0.1.1 代码变化

- 增加音频文件导入。在 App/Studio 走 SDK 用户选择文件接口，浏览器独立预览使用文件输入。新增可选 `files.user-selected` 权限，未扫描用户其他文件。
- 支持容器头识别 Ogg、WAV、MP3、M4A/MP4、WebM、FLAC；仅做头部与大小检查，不冒充完整解码验证。
- 最多 5 MiB，流读取过程中仍执行大小限制；不信任扩展名或宿主申报大小。
- 修复原后端把所有上传文件重命名为 `interview.ogg` 的问题。WAV 会保留 WAV MIME 与扩展名。
- 导入后不会立即上传；用户点击“转写音频”才发送到配置的服务。录音入口仍在用户主动停止后请求转写。
- 转写失败原因持续显示，可以重试或清除暂存音频；已有访谈状态不会被失败结果更新。
- 上游错误能显示“该key不允许访问该模型”等具体原因，服务端先脱敏，再返回前端。
- 模型单次请求限制 `max_tokens:2500`；密钥仍只在后端。
- 健康检查分别显示模型和 ASR 配置，强调配置存在不代表当前请求已验证成功。

自动测试 `npm test`：29 项通过，其中 5 项新增测试覆盖真实音频容器、扩展名错误、流大小限制和上游错误脱敏。ASR 测试仍使用测试代码伪造的上游响应，**没有真实云端转写成功的证据**。

准备了 `evidence/ASR测试_系统合成语音.wav`：macOS 系统 Tingting 合成的虚构测试句，9.884813 秒、16 kHz、单声道、PCM s16le、316392 字节。仅生成文件，尚未送入真实 ASR。不是用户录音或克隆声音。
