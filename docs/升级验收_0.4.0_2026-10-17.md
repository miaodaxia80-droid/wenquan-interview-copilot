# 问全 0.4.0 升级验收与部署记录

日期：2026-10-17。需求基线为项目需求 v0.5，软件版本为 0.4.0。根据本轮要求，实际更新公网网关，同时增加自动说话人角色识别、结束后整场归纳，精简主持人界面，并交付两人演示剧本。

## 已实现

- 流式 ASR 请求启用说话人信息；返回的 speaker_id 按每次采集流隔离。模型结合开场身份介绍和连续问答判断 host/guest；不凭编号、性别或单个问号判断。不确定保留 unknown，模型自报置信值低于 0.9 不采用；这不是识别准确率。
- 同一声音在本次采集沿用已绑定角色，人工更正优先。人工保留未知的片段不自动改写。冲突判断不绑定，不推断真实姓名或注册声纹。
- 角色识别结果在会话、版本或取消状态变化后不采用；新识别出的历史片段按时间顺序重新分析。未知和主持人片段不作为嘉宾事实来源。
- 点击结束会取消并等待当前分析、收尾稳定转写，再自动整理整场内容。输出核心收获、每条主线的归纳、待补问；每个要点带至少一个嘉宾原话引用，前后端均校验。
- 归纳包括整场转写，长内容逐块归纳后合并，不只处理近期实时窗口。上限 1500 段 / 24 万字符。章节摘要可以修改，保留人工保存的内容；更正源文本会撤回原派生内容并允许重新归纳。
- 会中突出当前一题、其余候选、最新发言和采集状态。文本演练、完整转写、问题历史、眼镜同步和高级设置折叠。新建只显示主持人访谈；旧主题、旧场景与 v1 接口保留。
- 修复准备页“分析设置”默认提交表单导致意外启动录音的问题，修复忙碌时结束可能跳过自动归纳的问题，保留异步刷新前未保存的自拟问题和章节编辑草稿。

## 原生 MemoMind Plugin Studio

使用已登录的原生 Studio，问全 0.4.0 配官方 GM Web Bridge v2。旧的六个主题记录仍可见，新建“第一个陌生用户之后 · 0.4 云端演练（虚构）”，明确保存公网地址后，用默认自动识别输入三段未标注角色的虚构文本。

实际观察：主持人开场识别为“主持人 · 自动”；嘉宾开场及后续经历均识别为“嘉宾 · 自动”；生成 2～3 个候选；点击已问后，后续原话被关联为回应，当前阅读问题保留，后续候选继续更新。结束后自动出现整场核心内容、四章归纳与待补问；展开原话可查。实际导出并读取 Markdown 文件。最终插件刷新后仍可恢复已保存归纳。
