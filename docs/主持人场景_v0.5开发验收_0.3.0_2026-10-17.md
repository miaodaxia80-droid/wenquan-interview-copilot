## 自动与真实模型检查

`npm run check`、`npm run build` 成功。`npm test`：**81 通过、0 失败、0 跳过**，包含既有 62 项和新增 19 项主持人测试；原启动测试显式选择 legacy FDE，以保留旧流程覆盖。

证据：[完整测试输出](../evidence/test-results-0.3.0.txt)。测试覆盖依据与角色校验、候选去重上限、问答状态、提前回答、修订失效、说话人范围、累积原话、v1/v2 HTTP 及模型缺省版本处理。服务端只补齐模型漏写的协议版本；显式错误版本继续拒绝。

运行 `node --env-file-if-exists=.env scripts/verify-host-interview.mjs`，六轮合成且明确标注角色的文本经本机 HTTP / NDJSON 调用真实模型，全部通过。检查项为结构和逐字出处有效、host / unknown 不写成嘉宾陈述、主持人问题识别、后续回应关联、提前记录后续章节、候选不超过 3。证据：[真实模型报告](../evidence/host-interview-live-model-0.3.0.json)。这不是固定 demo 输出，也不是音频分离、实录访谈或语义质量的全面证明。

## 原生 Studio 操作证据

保留旧主题，新建“主持人 v0.5 联调 · 虚构访谈”。确认文本访谈，不调用麦克风。当前调试地址为 `http://127.0.0.1:8790`，设备访问码留空，上游仍由现有本机私密配置提供。

1. 嘉宾开场输入“当时工作挺稳定的，但我总想试试自己的东西。”，真实模型产生一个起因追问。
2. 手动标记已问，等待回应；输入嘉宾制作工具、陌生人使用、不辞职及时间收费困惑的合成回答。
3. 模型关联前题回应，记录关键选择 / 困难章节，产生三个不同方向候选；选择第二题，眼镜同步并提示其他两题。
4. 记录自拟问题“如果回到第一天，你会先验证什么？”，进入已问待回应历史。
5. 暂停后候选操作不可用，眼镜清空；结束后进入按主线回看，眼镜保持空白。
6. 编辑保存起因摘要，重载后仍保留；实际下载 Markdown，核对摘要、已回应、完整对话片段，无 undefined 或旧清单重复段。
7. 最终构建重新被 Studio 发现并生成组合 ZIP；恢复记录、结束后更正入口可用。

证据文件：[候选与同步截图](../evidence/studio-0.3.0-candidates.jpg)、[暂停截图](../evidence/studio-0.3.0-paused.jpg)、[会后截图](../evidence/studio-0.3.0-results.jpg)、[Studio 实际导出 Markdown](../evidence/Studio主持人合成访谈_0.3.0.md)。截图包含本机安装分享入口，仅作为本地验收资料。

Studio 刷新偶发 about:blank，已通过手机选择“未选择”再选择问全恢复，未覆盖旧存储。新增 `npm run start:studio` 提供可复现的 8790 回环开发入口；明确保存的 Studio 地址会保留，实机仍拒绝使用 Mac 回环地址。
