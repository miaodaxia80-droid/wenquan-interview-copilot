# App 端 ASR 能否直接供问全调用

2026-10-17。结论：App 自身有识别实现的静态证据；当前公开 Web Bridge 没有提供插件启动 ASR 或接收识别文本的接口，问全目前不能直接复用它。不能把“没有公开入口”扩大成“厂商技术上做不到”。

## 本次核对依据

- 本地 SDK 的 `PhoneSDK/docs/web-plugin/api-reference.md` 和 `capability-contract.md`：原生控制方法为 `audio.openCapture`、`audio.stopCapture`；返回 Opus 音频流，事件 `audio.captureState` 表示采集状态。`gm.audio.openRecording` 是 Web SDK 在采集流上封装的帮助方法，返回音频，不是转写文本。
- 再次查看[官方在线 API](https://github.com/memomind-open/plugin-open-platform/blob/main/PhoneSDK/docs/web-plugin/api-reference.md)和[权限契约](https://github.com/memomind-open/plugin-open-platform/blob/main/PhoneSDK/docs/web-plugin/capability-contract.md)，同样未见 ASR 启动/停止或识别结果方法、权限、事件。没有向宿主发送猜测的 `asr.start` 等内部请求。
- 对先前提取的 Android Flutter AOT `libapp.so` 过滤静态字符串，发现 `CommonAsrEngine`、`AiAsrRepository`、`startAsr`、`asrText` 和长录音离线识别的 Android channel 名。相同文件也有公开 Bridge 的 `audio.openCapture`、`runtime.getCapabilities`，但命名空间字符串中未见 `asr.*` / `speech.*` 转写入口。内部 Dart 符号或 Android channel 名并不等于 WebView 插件可调用。
- 检查结果和提取文件 SHA-256 见 `evidence/android-asr-bridge-inspection.json`；原 APK 版本 1.3.81 的身份、哈希与完整静态边界见上级目录 `MemoMind_APK静态检查_2026-10-16.md`。本次重新分析的是已有提取文件，没有重新找到和校验原 APK，也没有完成业务代码反编译。
- 本机没有可用的 `adb` 命令，本次没有 Android 运行实例的能力查询、原生 ASR 调用、麦克风录制或转写回调证据。桌面 Studio 的成功不能证明 Android ASR 可用。

## 最短接入路径

如果 MemoMind 厂商开放插件转写入口，问全可接收文本并复用现有的原话核对、保存分析和眼镜显示。需要厂商确认的具体内容是：

> MemoMind Android App 1.3.81 的 Web 插件能否复用 App 内置在线/离线 ASR？如支持，请提供 Bridge 方法、manifest 权限、结果事件和样例，包含 partial/final 区分、片段 ID、时间戳、停止及后台生命周期规则。另请说明与 App 字幕、长录音及插件 audio.capture 的音频资源占用和冲突行为；对应最低 App/固件版本是什么？

这是本地待询问文本，未发送给任何人。当前契约的音频通道有独占约束，不能预设 App 的 ASR 与插件录音能同时运行。

取得真实接口后，应在 Android 中验证：主动开始 → 识别中间结果 → 最终片段 → 用户核对 → 保存分析 → 眼镜显示；停止、后台和退出后不得继续接收旧会话结果。

当前可用方式是人工把 App 转写文本粘贴到问全；自动方式需要独立 ASR 服务，或由厂商补上 App 到插件的转写桥接。问全已有音频采集、文件导入和可替换的后端转写适配器，但尚无真实 ASR 转写成功记录。
