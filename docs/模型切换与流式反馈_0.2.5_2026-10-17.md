# 0.2.5 模型切换与流式反馈

2026-10-17。当前源码工作树未提交、推送或公开发布。个人安装包保留免配置连接；上游密钥仅保存在服务端私密配置，不进入手机包。

## 最终模型与取舍

默认改为火山 Agent Plan **DeepSeek V4.1 Flash**，API alias `deepseek-v4.1-flash`，Base URL `https://ark.cn-beijing.volces.com/api/plan/v3`。请求 `stream:true`、`thinking:{type:"disabled"}`、`response_format:{type:"json_object"}`。ASR 仍用原来的 Agent Plan 豆包流式 2.0，前台连续采集、增量 Ogg Opus 和 WSS 不变。

官方 [Agent Plan 套餐概览](https://docs.volcengine.com/docs/ark/agent-plan-personal-plan-overview?lang=en)列出该模型；套餐 URL 与按量计费 `/api/v3` 不同，本次没有切到按量计费接口。

曾比较 Doubao Seed 2.0 Mini、2.1 Lite。Mini 在若干长历史样例中出现错误片段 ID、把部分回答标作完整，以及重复追问；无效输出被校验拒绝。增加明确 currentSegment 输入后重测，并扩大到 V4.1 Flash。最终模型在短样例和带历史样例上更快，且正确保留资料维护人等未确认事项为 vague，因此选它作为默认。GLM 5.3 Flash 的 `thinking:disabled` 请求被该接口拒绝；不能据此说模型整体不可用，也没有将其纳入成功测速。

## 相同任务的实际测速

`evidence/selected-model-benchmark-0.2.5.json` 使用同一分析适配器、相同系统提示和同类合成访谈上下文。原模型按旧应用方式等待完整 JSON；新模型读取实际 SSE 增量。各场景各一次，固定顺序，无并发、无统计显著性或线上延迟保证。

| 合成场景 | 原京东云 V4 Flash 完整结果 | Agent Plan V4.1 Flash 完整结果 | 新模型追问草稿文字就绪 |

| 工单流程与主管未回复 | 3.640 s | 1.816 s | 0.778 s |
| 报名验证码障碍 | 5.549 s | 2.213 s | 0.900 s |

前 3 个实质分析样例平均完整耗时约减少 52%；所有 4 个平均约减少 47%。极短空分析原模型更快。新模型的 4 个结果都通过结构与逐字引文校验，没有触发自动重试。首次内容为 0.71–0.77 s，不能与完整可用追问混为一谈。

带 9 段合成历史的额外测试：新片段与逐字引用校验通过，完整分析约 1.56–1.67 s；明确未知的兜底流程和资料维护人保留为 vague。见 `evidence/long-context-deepseek-v4.1-flash-0.2.5.json`。这些样例不构成语义准确率或冲突检测能力评估。

## 用户可见行为

- 一发起分析便显示连接/生成阶段和已等待时间；连续采集与转写可继续进行。
- 上游 SSE 经网关转成鉴权 NDJSON 增量，手机处理拆包与 UTF-8 边界。已生成的追问文字以“草稿，核对通过后更新到眼镜”展示；不把 JSON 或推理过程直接放到界面。
- 只有完整结果通过服务器与手机的结构、片段 ID、逐字引用校验后，才更新记录、事项和眼镜。草稿不写入访谈，不发送眼镜。
- 校验拒绝后最多重新核对一次，并重置手机草稿；再次失败保留原话供重试。取消、切换访谈、结束和流中断都不能提交半成品。
- future/hypothesis/unknown 的 stated 输出降为 vague，避免将非当前事实计为具体回答；模型语义仍须人工判断。
- 分析完成后先刷新手机，再异步发送眼镜，眼镜接口等待不阻塞下一个分析。录音停止通知也会正确更新。
- 旧 JSON API 保留，0.2.4 手机立即使用新云端模型；0.2.5 才显示新增的流式反馈。没有流读取能力的宿主仍可走 JSON。
