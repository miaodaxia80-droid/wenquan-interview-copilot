# 0.5.5 主线建议与眼镜显示

## 行为

- 确认准备后，零语音输入即可展示当前主线的主问题。这条建议直接来自已确认提纲，不需要模型请求。
- 没有新语音时保留建议，不按静默时长轮播、不把沉默当成回答。新增语音尚未分析或 ASR 尚有积压时，不据此生成下一条主线。
- 嘉宾回答经已有 v2 协议识别后，有效的模型追问或转场优先于本地主线建议。模型原有阅读稳定规则保留；实际回答匹配或有效性复核可撤下旧题。
- 主问题已被有出处的回答关联，且没有其他候选时，补上下一条未处理主线的建议。只有零散陈述不会把整章判定完成。
- 点击“已问”保留问题在眼镜上，标注“等待回答”，不自动选中其他候选；可手动选题或切章改变关注点。不会因为显示过就记为已问。
- “稍后”和“略过”可继续建议下一条主线，但不算已答。所有主线处理后给一次收尾建议；不自动结束访谈。手动标记聊完的章节不再生成主线题。
- 本地主线建议、原话追问和转场均是可选建议。眼镜增加章节位置、章节名、下一条主线，底部标注“建议 · 自由选择”。已问待回应状态显示等待提醒。
- 长自定义提纲保留完整文本在手机与模型上下文，眼镜用章节名组成完整短问句，避免截断成半句。
- 暂停或结束仍清屏。旧版 v1 访谈不改变业务流程。存储分块、reviews 和 interviewSummary 修复保留。

## 实现范围

源文件为 web/interview.js、web/app.js、web/glass-ui.js、web/interview-ui.js、web/style.css。更新版本信息及 design/glasses.html 的真实渲染示例。复用既有 gm display 协议和 GM Web Bridge v2，未改公共 SDK、原生 GMP、权限或服务端。公网网关沿用既有部署。

本地主线建议不计入模型生成到眼镜显示的延迟样本；完整数据仍通过 0.5.4 的分块存储保存。
